# CodexBar 今日 Token 与弹窗重设计规格

## 目标

在不改变菜单栏额度文案的前提下，为 CodexBar 增加“今日使用 Token”统计，并按已确认的方案 A 重设计弹窗。界面应突出今日 Token、清晰展示两类额度、提供可感知的刷新状态，同时保持原生 macOS 菜单栏应用的紧凑感。

## 数据来源与语义

- 继续通过本机已登录的 `codex app-server --stdio` 获取数据，不读取凭据文件。
- 额度使用 `account/rateLimits/read`；今日 Token 使用 `account/usage/read`，请求参数为 `null`。
- `dailyUsageBuckets` 中 `startDate` 与 macOS 当前本地日期一致的记录作为今日用量，`tokens` 使用 `Int64`。
- `dailyUsageBuckets` 存在但没有今日记录时显示 `0 tokens`；字段缺失、响应畸形或请求失败时显示 `--`，不能伪造为零。
- Token 为账户级按日聚合数据，每 60 秒轮询并支持手动刷新。服务端可能在一次任务结束后才计入，因此文案定位为“准实时”，不宣称逐 Token 流式更新。
- 不展示或持久化 lifetime、峰值、连续使用天数等未请求指标，也不保存 Token 历史。

## 状态与容错

额度和 Token 独立发布状态：任一接口失败不得阻止另一项成功更新。额度继续缓存最后有效快照；Token 只在当前进程内保留最后成功值，失败时标为过期，重启后不把昨日值当作今日值。

“刷新”同时请求额度和今日 Token，并依次显示“刷新中…”与“已刷新”。若只有一项失败，界面保留成功项并明确指出另一项暂不可用。连接中断继续触发现有指数退避重连。

## 颜色规则

- 剩余 `51%...100%`：绿色。
- 剩余 `21%...50%`：黄色。
- 剩余 `0%...20%`：红色。
- 数据过期或缺失：灰色。

每个额度百分比和进度条使用自身等级颜色。菜单栏文字、弹窗状态圆点使用主状态色：存在 5 小时额度时取 5 小时等级，否则取每周等级。今日 Token 是消耗量而非剩余额度，始终使用中性色。

## 弹窗布局

采用已确认的方案 A 增强版，宽度约 350 点：

1. 顶部左侧显示 `CodexBar` 与数据状态，右侧为带边框的“刷新”按钮。
2. 第一信息层级显示“今日使用”和带千位分隔的 `<数量> tokens`。
3. 第二层级按行显示 5 小时与每周额度：标题、百分比、线性进度条和重置时间。
4. 5 小时数据缺失时整行隐藏，每周行保留。
5. 底部保留“登录时自动启动”和“退出 CodexBar”。
6. 移除整块额度色背景和等权卡片；颜色只用于状态、百分比与进度条。

菜单栏继续显示 `5h <百分比>% · 周 <百分比>%`；5 小时缺失时只显示 `周 <百分比>%`，不把今日 Token 加入菜单栏。

## 测试与验收

- DTO 能解码 CLI 0.147.0 的完整 `account/usage/read` 响应。
- 今日日期匹配、当天无记录、字段缺失和负数 Token 均有领域测试。
- 客户端使用正确方法名并在断线后只重连重试一次。
- 额度成功/Token 失败、Token 成功/额度失败、并发刷新合并和停止失效均有视图模型测试。
- 颜色边界精确覆盖 51、50、21、20。
- Swift 全量测试、应用构建通过；人工检查模式覆盖明暗外观、5 小时缺失、刷新三态及三档额度颜色。

## 安全与兼容

不记录 App Server 原始响应，不输出认证信息，不启用不必要的实验能力。新增模型保持旧 `UsageSnapshot` 缓存兼容；现有图标资源和安装脚本修改不属于本功能范围。
